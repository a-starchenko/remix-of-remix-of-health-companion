# Skill: shadcn/ui Design System

This skill captures **how the UI primitive layer was generated**, not the bespoke screens.

It is intentionally thin: it pins only the *project-specific seed* (config, theme tokens, installed component list) from which the shadcn CLI/MCP can regenerate everything. For how shadcn itself works (registry, the `add` command, component anatomy), defer to upstream — don't duplicate it here.

- **Upstream docs:** <https://ui.shadcn.com/docs>
- **shadcn MCP:** <https://ui.shadcn.com/docs/mcp>

---

## Provenance boundary (read this first)

| Path | Origin | Rule |
|---|---|---|
| `src/components/ui/*` | shadcn registry output | **Do not hand-edit.** Regenerate via CLI/MCP; customise through theme tokens or composition, not by patching generated files. |
| `src/pages/*`, `src/components/{chat,layout,settings}/*` | bespoke, generated by Lovable | Out of scope for this skill — the product screens are not shadcn registry items. |

This skill reproduces the **design system** (primitives + tokens), not the application screens.

## The reproducible seed

Four inputs are enough for the CLI/MCP to recreate the primitive layer. Everything else is derived.

### 1 — `components.json` (already committed)

```json
{
  "$schema": "https://ui.shadcn.com/schema.json",
  "style": "default",
  "rsc": false,
  "tsx": true,
  "tailwind": {
    "config": "tailwind.config.ts",
    "css": "src/index.css",
    "baseColor": "slate",
    "cssVariables": true,
    "prefix": ""
  },
  "aliases": {
    "components": "@/components",
    "utils": "@/lib/utils",
    "ui": "@/components/ui",
    "lib": "@/lib",
    "hooks": "@/hooks"
  }
}
```

`cssVariables: true` means theming is driven by HSL CSS variables (below), not hard-coded Tailwind colors.

### 2 — Theme tokens

Source of truth: `src/index.css` (`:root` + `.dark`) and `tailwind.config.ts` (`theme.extend`). Key brand decisions to preserve on a rebuild:

| Token | Value | Notes |
|---|---|---|
| Font | `DM Sans` | Loaded from Google Fonts in `src/index.css`; set as `font-sans` |
| `--primary` | `168 76% 32%` (teal) | Brand color; dark mode `168 65% 45%` |
| `--radius` | `0.75rem` | Drives `lg/md/sm/xl/2xl` radii |
| `--destructive` | `0 84% 60%` | |

**Project-specific custom tokens** (beyond the shadcn defaults — these are *not* part of the registry and must be re-added by hand after `init`):

- `--chip-bg` / `--chip-text` / `--chip-hover` → Tailwind `chip.{DEFAULT,foreground,hover}`
- `--surface-elevated` / `--surface-subtle` → `surface.{elevated,subtle}`
- `--chat-user` / `--chat-assistant` → `chat.{user,assistant}`
- `--success` / `--warning` (+ `-foreground`) → `success.*`, `warning.*`
- `--shadow-soft|card|elevated` → `boxShadow.{soft,card,elevated}`
- Custom keyframes/animations: `fade-in`, `slide-up`, `scale-in` (+ `accordion-*`)

Plugins: `tailwindcss-animate`, `@tailwindcss/typography`.

### 4 — Adding / regenerating components (CLI or MCP)

In this project the component set arrived bundled with the Lovable starter — neither the shadcn CLI nor the MCP was invoked by hand. For a from-scratch rebuild, or to add new components later, use the shadcn CLI (`npx shadcn@latest add <name>`) or the official **shadcn MCP**, which lets an agent browse the registry and add components without leaving the editor. To make the MCP available, configure it in `.cursor/mcp.json`:

```json
{
  "mcpServers": {
    "shadcn": { "command": "npx", "args": ["-y", "shadcn@latest", "mcp"] }
  }
}
```

No secrets are involved, so this file is safe to commit. See <https://ui.shadcn.com/docs/mcp> for the current invocation and available tools.

## Rebuild recipe

On a fresh starter (see `fork-starter`):

1. `npx shadcn@latest init` — answer to match `components.json` above (or drop the file in first).
2. Restore the theme tokens in `src/index.css` and the `theme.extend` block in `tailwind.config.ts` (the custom tokens in §2 are **not** restored by `init`).
3. `npx shadcn@latest add <the 48 items from §3>`.
4. (Optional) Add the shadcn MCP (§4) so further components can be pulled on demand.

After this the primitive layer matches; the bespoke screens come from the Lovable base, not from here.

## Conventions

- **Never hand-edit `src/components/ui/*`** — re-pull or extend via composition / theme tokens.
- **New primitive** → `npx shadcn@latest add <name>` (or the MCP), never copy-paste source.
- **New color/spacing** → add a CSS variable in `src/index.css` *and* map it in `tailwind.config.ts`; don't hard-code hex values.
- Render Markdown (chat replies) with `react-markdown` + `remark-gfm`; long-form text uses the `@tailwindcss/typography` `prose` classes.
